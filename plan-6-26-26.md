# Plan: Lid Status, Battery SOC Display, Sleep Mode

## Context

Three remaining features need implementation:
1. **Lid Status** — GPIO bit mapping is wrong (bit 0 vs bit 1); feature defaults to disabled
2. **Battery SOC Display** — INA219 coulomb counting exists in the driver but the battery_service and UI only show raw voltage (39.25V because INA219 isn't wired to the power rail). Need SOC-based display per `ina219.md` spec
3. **Sleep Mode** — Zero code exists. Design documented in `SLEEP_MODE_PLAN.md` and `lockbox_functions.md`

The INA219 driver (`ina219_monitor.c`) already has coulomb counting, SOC, level state machine, and NVS persistence. The gap is the battery_service only exposes voltage, and the home screen shows that voltage (incorrectly). The INA219 driver itself needs valid I2C hardware data — the 39.25V means the sensor isn't wired correctly, but the code flow is correct once the hardware is fixed.

## Feature 3: Sleep Mode

### NEW: `main/services/sleep_service.h`

```c
typedef enum {
    SLEEP_STATE_ACTIVE = 0,
    SLEEP_STATE_COUNTDOWN,
    SLEEP_STATE_DEEP_SLEEP,
} sleep_state_t;

typedef struct {
    sleep_state_t state;
    bool lid_closed;
    bool user_logged_out;
    bool face_module_stowed;
    bool lock_engaged;
    uint16_t countdown_seconds;
} sleep_check_result_t;

esp_err_t     sleep_service_init(void);
sleep_state_t sleep_service_get_state(void);
void          sleep_service_tick(void);               // called from UI every 1s
void          sleep_service_activity_detected(void);  // called on any user action
esp_err_t     sleep_service_check_entry(sleep_check_result_t *result);
esp_err_t     sleep_service_enter(void);
void          sleep_service_wake(void);
```

### NEW: `main/services/sleep_service.c`

Implementation:
- **Inactivity timer**: `esp_timer` tracking last activity; default 5 min timeout (configurable via Kconfig)
- **Countdown**: After inactivity, 60-second countdown UI toast
- **Precondition check** (all four must be true):
  1. `status_inputs_read()` → `!inputs.lid_open`
  2. `!session_service_is_authenticated()` (user logged out)
  3. `status_inputs_read()` → `inputs.face_module_stowed`
  4. `lock_service_get_state()` → `is_locked`
- **Sleep entry**: `ch422g_backlight_control(i2c, false)` then `esp_deep_sleep_start()`
- **Wake**: Check `esp_reset_reason() == ESP_RESET_DEEP_SLEEP` in `app_main()`; call `sleep_service_wake()` to restore backlight, show start screen
- **Task**: Lower-priority FreeRTOS task (priority 3) running tick loop

### `main/Kconfig.projbuild` — Add sleep config

After the INA219 entry:
```kconfig
        config LOCKBOX_FEATURE_SLEEP_MODE
            bool "Enable sleep mode"
            default n
            depends on LOCKBOX_FEATURE_STATUS_INPUTS

        config LOCKBOX_SLEEP_INACTIVITY_TIMEOUT_S
            int "Inactivity timeout before sleep countdown (seconds)"
            default 300

            depends on LOCKBOX_FEATURE_SLEEP_MODE
```

### `main/app/lockbox_app.c` — Initialize sleep service

After status_service init:
```c
#if CONFIG_LOCKBOX_FEATURE_SLEEP_MODE
    err = sleep_service_init();
    if (err != ESP_OK) ESP_LOGW(TAG, "sleep_service_init failed: %s", esp_err_to_name(err));
#endif
```

### `main/main.c` — Wake detection

After `lockbox_app_init()`:
```c
if (esp_reset_reason() == ESP_RESET_DEEP_SLEEP) {
    ESP_LOGI(APP_TAG, "Woke from deep sleep");
    sleep_service_wake();
    lv_scr_load(ui_screen_start);
}
```

### `main/ui/screens/ui_screen_home.c` — Sleep integration

- Add `sleep_service_tick()` call via LVGL timer (every 1s) when home screen active
- Add `sleep_service_activity_detected()` to all button event handlers (unlock, change_pin, register, admin, signout)
